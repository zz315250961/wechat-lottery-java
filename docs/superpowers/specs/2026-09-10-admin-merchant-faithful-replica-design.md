# 管理员端与商户端旧版界面一比一复刻设计

## 1. 目标与不可变约束

本次只复刻旧版系统的界面、信息结构、交互方式和响应式行为，不复制旧版 React/Node 源码。新版技术栈保持 Vue 3 + Vite + JavaScript、Spring Boot 2.5.15 + Java 8 + MyBatis-Plus、MySQL 8、Redis。

视觉与交互唯一基准为 `F:\Desktop\codex\抽奖` 旧版系统及用户提供的旧版截图。不得自行新增另一套视觉语言，不得套用若依默认深色侧栏、顶栏、多标签页、组织树或默认表单布局。

## 2. 三端名称

浏览器标题必须按三端固定区分，不随当前页面、路由或商户名称变化：

- 用户端：`幸运抽奖`
- 管理员端：`幸运抽奖｜活动管理后台`
- 商户端：`幸运抽奖｜商户核销工作台`

页面左上品牌固定为“幸运抽奖”，管理员副标题固定为“活动管理后台”；商户端品牌区显示真实商户名称，副标题固定为“商户核销工作台”。

## 3. 管理员端整体框架

管理员端完全复刻旧版双栏结构：左侧固定暖白导航，右侧为内容工作区。使用旧版暖橙主色、灰褐正文、细边框、低阴影、圆角控件和相同的留白密度。

左侧业务菜单顺序固定为：

1. 奖池管理
2. 活动设置
3. 外观主题
4. 公告规则
5. 商户管理
6. 参与用户
7. 中奖与核销

“定向中奖”不在菜单显示，继续通过 3 秒内连续点击左上“幸运抽奖”3 次进入。

系统能力菜单位于业务菜单之后，视觉与旧版菜单一致，不嵌套若依原生界面：

1. 后台用户管理
2. 角色权限
3. 在线用户
4. 服务器监控
5. Redis 缓存
6. 登录日志
7. 操作日志

底部固定“打开抽奖页面”“退出登录”和桌面端“收起菜单”。手机端侧栏改为抽屉，内容、顺序、样式不变。

## 4. 管理员业务页面逐页复刻

### 4.1 奖池管理

复刻旧版行内商品管理：摘要、模糊搜索、添加奖品、商品图片与上传、名称、所属商户、概率、库存、已抽中、已核销、每人上限、有效期/固定核销时间、启用、排序、删除和底部统一保存。桌面为旧版横向表格；手机为同字段卡片重排，不弹出通用编辑框。

### 4.2 活动设置

复刻旧版设置卡片和字段排列，包含活动标题、说明、开始/结束时间、每日免费次数、签到奖励、助力奖励、每日助力上限、未中奖提示、活动开关与保存反馈。只在真实修改后提示未保存。

### 4.3 外观主题

复刻旧版颜色选择、封面图、背景图和图片预览上传区域；实时预览与保存行为沿用旧版。

### 4.4 公告规则

复刻旧版公告与规则编辑列表，支持新增、删除、排序、启停和保存；用户端只展示启用项。

### 4.5 商户管理

复刻旧版商户资料编辑卡片，不使用若依通用用户弹窗。每个商户展示名称、账号、地址、使用规则、启用状态、密码修改和独立保存。商户账号归属只在本页管理。

### 4.6 参与用户

复刻旧版摘要、即时模糊搜索和数据表，展示真实昵称、手机号、OpenID、抽奖次数、奖券数、状态等数据。用户统计必须从抽奖记录和奖券记录实时聚合。

### 4.7 中奖与核销

复刻旧版搜索、摘要和记录表，展示奖品、中奖用户、手机号、券码、状态、中奖时间、核销时间；管理员视角可显示商户，商户端不重复显示本店名称。

### 4.8 定向中奖

复刻旧版隐藏页面的同一行用户模糊搜索、奖品搜索、次数设置、添加反馈和现有配置列表。

## 5. 若依系统能力页面

这些页面继续调用若依真实接口和权限能力，但完全移除若依默认 Layout、TagsView、面包屑、组织机构树和蓝色控件，使用管理员端统一外壳与旧版组件。

### 5.1 后台用户管理

只显示拥有管理员类角色的后台账号，不显示商户账号和参与抽奖用户。字段为账号、昵称、手机号、角色、状态、创建时间和操作。支持搜索、新增、编辑、启停、重置密码、删除；不得展示乱码昵称或虚构组织数据。

### 5.2 角色权限

展示真实若依角色，支持新增、编辑、状态、数据权限、菜单权限和删除。权限选择使用符合旧版样式的居中自定义弹窗。

### 5.3 数据监控与日志

在线用户、服务器监控、Redis 缓存、登录日志、操作日志继续使用若依真实接口；重新编排为旧版暖橙卡片、筛选栏和表格。不得显示与抽奖项目无关的演示数据。

## 6. 商户端逐页复刻

### 6.1 登录页

复刻旧版居中登录卡片，标题为“商户核销工作台”，保留账号、密码、登录状态和明确错误提示，不出现若依后台登录页。

### 6.2 核销工作台

复刻旧版商户页：真实商户品牌头、核销顾客奖券标题、券码输入、查询奖券、全屏扫码、核销前奖品图片与用户信息预览、二次确认、成功反馈、本店奖券记录和搜索。

### 6.3 全屏扫码

相机占满可视区域，扫码成功后自动回到核销工作台并填充券码，不在核销表单内嵌小相机画面。

## 7. 数据边界与纠错

- 管理员账号：`sys_user` 中拥有管理员类角色的账号，仅出现在“后台用户管理”。
- 商户账号：绑定 `lottery_merchant` 或拥有商户角色的账号，仅出现在“商户管理”。
- 参与用户：`lottery_user`，仅出现在“参与用户”。
- 角色与权限：使用真实 `sys_role`、`sys_user_role`、菜单权限数据。
- 删除或修复当前测试库中乱码昵称、错误部门关联和无意义组织树数据；不虚构新的组织结构。
- 奖品库存、已抽中、已核销、用户抽奖次数和奖券数均从真实业务记录聚合，所有页面共用同一数据口径。

## 8. 响应式与可用性

- 桌面端以旧版 1440px/1920px 截图为一比一基准。
- 管理后台在手机上使用抽屉导航；表格转换为可操作卡片或必要的横向滚动，不隐藏核心功能。
- 商户端优先适配微信内置浏览器、Android Chrome 和 iPhone Safari。
- 所有触控目标至少 44px；弹窗在手机上不溢出；图片保持比例并提供失败回退。

## 9. 实施方式

1. 逐页提取旧版 DOM 信息结构、尺寸、颜色、间距、图标和交互状态。
2. 在 Vue 3 中建立旧版风格的共用后台组件，不导入旧版 React 组件或业务代码。
3. 将业务页逐个迁入统一外壳。
4. 为若依系统能力页建立旧版风格适配层，并修正账号分类和数据范围。
5. 完成商户登录、核销、记录和全屏扫码复刻。
6. 对桌面与手机逐页截图，与旧版同状态并排比对，修正 P0/P1/P2 偏差。

## 10. 验收标准

- 每个页面的导航、标题、字段、图片、操作位置、色彩、间距和交互与旧版一致。
- 三端浏览器标题在同时打开时可立即区分。
- 管理员、商户、参与用户三类账号和数据不混用。
- 后台用户无乱码、无错误组织树、无商户账号混入。
- 业务统计在奖池、参与用户、中奖核销和商户记录之间一致。
- 所有保存、删除、启停、上传、核销操作均有旧版风格反馈。
- 桌面端和手机端主要流程均通过真实接口测试。
- 前端生产构建、后端测试和逐页视觉 QA 全部通过。
