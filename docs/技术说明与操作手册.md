# 校园幸运抽奖系统：技术说明、业务流程与操作手册

## 1. 项目定位

这是旧系统的独立重写版，只复刻业务功能和交互目标，不包含旧 React、Node、SQLite 源码或旧业务数据。用户端、商户端、管理端共用一套 Java API 和 MySQL 数据源。

## 2. 技术栈

- 后端：Java 8、Spring Boot 2.5.15、若依 3.9.2、Spring Security、MyBatis-Plus 3.5.3.1、MySQL 8、Redis、Maven。
- 前端：Vue 3、Vite、JavaScript、Vue Router、Pinia、Element Plus、jsQR、QRCode、Lucide。
- 微信：公众号网页 OAuth、公众号用户信息、关注状态、JS-SDK 签名、好友/朋友圈分享卡片。
- 数据原则：MySQL 是业务真实数据源；Redis 只存登录会话、微信票据、限流与临时状态。

## 3. 目录和文件职责

### 后端

- `backend/pom.xml`：父工程、Java/Spring Boot/MyBatis-Plus 版本及模块清单。
- `backend/ruoyi-admin`：应用入口、Spring 配置、数据库/Redis/上传路径配置。
- `backend/ruoyi-framework`：若依安全认证、JWT、权限、限流和全局基础设施。
- `backend/ruoyi-system`：管理员与商户系统账号、角色和系统配置。
- `backend/ruoyi-lottery`：全部抽奖业务代码。
- `controller/LotteryPortalController`：用户登录、状态、签到、助力、抽奖、奖券。
- `controller/LotteryMerchantController`：本店奖券查询和核销。
- `controller/LotteryAdminController`：活动、奖池、规则、商户、用户、记录、定向中奖。
- `controller/LotteryUploadController`：JPG/PNG 安全上传。
- `controller/WechatController`：微信授权回调和 JS-SDK 配置。
- `service/LotteryPortalService`：用户业务事务和抽奖闭环。
- `service/LotteryMerchantService`：商户归属检查、过期检查和事务核销。
- `service/LotteryAdminService`：管理端配置和真实统计。
- `service/WechatService`：OAuth、用户资料、关注状态、access_token/jsapi_ticket 缓存。
- `mapper/LotteryPortalMapper`：抽奖业务 SQL；活动/奖品 Mapper 使用 MyBatis-Plus。
- `src/test`：概率、次数、会话、核销、上传、账号与微信签名领域测试。

### 前端

- `frontend/src/views/lottery/Consumer.vue`：手机用户端转盘、公告、登录、签到、助力、券包和分享。
- `frontend/src/views/lottery/Merchant.vue`：商户登录、记录搜索、全屏扫码和确认核销。
- `frontend/src/views/lottery-admin/index.vue`：管理工作台；三击标题进入隐藏定向中奖。
- `frontend/src/components/LotteryConfirm.vue`：项目风格居中确认弹窗。
- `frontend/src/api/lottery/index.js`：三端业务 API。
- `frontend/src/utils/auth.js`：管理员与商户使用不同 7 天 Token，避免互相覆盖。
- `frontend/src/router/index.js`：`/`、`/merchant`、`/admin` 三端入口。

### 数据与配置

- `sql/lottery_schema.sql`：业务表结构和初始活动，不包含测试业务数据。
- `backend/sql/ry_20260417.sql`：若依系统表。
- `.env.example`：环境变量样例，无真实密码或 AppSecret。
- `docs/plans/2026-09-10-ruoyi-rebuild-plan.md`：重写实施与验收计划。

## 4. 核心数据表

- `lottery_activity`：活动开关、起止时间、每日次数、公告和主题。
- `lottery_rule`：活动规则。
- `lottery_merchant`：商户与若依账号绑定、地址、使用规则。
- `lottery_prize`：概率、库存、个人上限、有效天数和核销截止时间。
- `lottery_user`：OpenID/UnionID、昵称、头像、手机号、关注和启停状态。
- `lottery_daily_usage`：按北京时间自然日记录签到、助力奖励和已用次数。
- `lottery_assist`：邀请人与助力人，同一好友同日只能助力一次。
- `lottery_directive`：管理员隐藏设置的定向奖品和剩余次数。
- `lottery_draw`：每次抽奖及唯一请求编号。
- `lottery_ticket`：奖券快照、核销码、商户信息、规则、有效期和核销状态。

## 5. 业务流程

### 用户参与

1. 打开 `/`，读取公开活动、公告、规则和奖池展示。
2. 正式环境进入微信 OAuth；开发环境可用手机号和固定四位验证码。
3. 后端建立 7 天 HttpOnly 用户 Cookie，刷新不退出。
4. 用户签到或获得好友助力，奖励计入当天可抽次数。
5. 抽奖请求携带唯一 `requestId`；重复请求返回同一结果，不重复扣次数或库存。
6. 事务内锁定活动，检查活动、用户、次数、个人上限、定向配置与库存。
7. 中奖时原子扣库存，写抽奖记录和奖券快照；未中奖也写抽奖记录。
8. 用户券包展示奖品图、二维码、商家位置、独立规则和截止时间。

### 好友助力

1. 登录用户分享带 `inviter` 的专属链接。
2. 好友打开后先完成登录，页面自动续办助力，无需二次点击。
3. 禁止自己助力、同一好友当日重复助力和超过活动每日上限。

### 商户核销

1. 商户访问 `/merchant`，使用管理端创建的账号登录。
2. 点击打开相机后进入全屏取景；识别二维码即停止摄像头、返回核销页并填入券码。
3. 商户核对后点击确认；后端校验券属于本店、未核销且未过期。
4. 事务更新核销状态、时间和操作人；本店记录显示奖品与核销用户，不重复显示商户列。

### 管理配置

1. 管理员登录 `/admin`。
2. 配置活动开关、起止时间、次数、公告和规则；活动不会每天自动关闭，每天只重置用户日次数。
3. 创建商户会同步创建 BCrypt 密码的若依账号。
4. 配置奖品、图片、商户、概率、库存、个人上限、有效期和核销截止时间，并可调整转盘顺序或停用奖品。
5. 活动可设置开始/结束时间、主题色、背景色、背景图和分享封面；结束时间留空代表长期有效，不会每天自动关闭。
6. 在参与用户页可搜索并启用或停用用户。
5. 库存中奖时实时减少；“已抽中”“已核销”均从真实记录聚合。
6. 用户与中奖核销页面支持模糊搜索。
7. 管理员在 3 秒内连续点击左上“幸运抽奖”3 次进入定向中奖。

## 6. 本地启动

1. 安装 JDK 8、Maven、Node.js、MySQL 8。
2. 启动 `F:\Desktop\redis-2.8.9\redis-server.exe`，仅绑定 `127.0.0.1`。
3. MySQL 依次执行 `backend/sql/ry_20260417.sql`、`sql/lottery_schema.sql`。
4. 复制 `.env.example` 的配置到本机环境，生产环境必须替换数据库密码和 `TOKEN_SECRET`。
5. 后端：进入 `backend`，执行 `mvn install`；再进入 `ruoyi-admin` 执行 `mvn clean package` 和 `java -jar target/ruoyi-admin.jar`。
6. 前端：进入 `frontend`，执行 `npm install`、`npm run dev`。
7. 生产构建：后端 `mvn test`，前端 `npm run build:prod`。

## 7. 微信配置

需要在部署环境设置：`WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`LOTTERY_PUBLIC_BASE_URL=https://正式域名`。公众号后台网页授权域名只填写域名，不带协议和路径；JS 接口安全域名填写相同正式域名。强制关注时设置 `WECHAT_REQUIRE_FOLLOW=true`。普通公众号网页 OAuth 不提供手机号，本系统从微信获取 OpenID、昵称和头像；手机号能力需要另行开通微信对应产品能力。

## 8. 安全说明

- 用户 Cookie、管理员 Token、商户 Token 相互隔离且有效期 7 天。
- 商户密码 BCrypt，不保存明文；生产环境禁止弱密码。
- 登录、签到、助力、抽奖、核销均有 Redis/IP 限流。
- 数据库唯一键防止重复助力和重复抽奖请求。
- 活动行锁和库存条件更新防止并发超卖。
- 跨店、过期、已核销券由服务端拒绝，前端状态不可作为安全依据。
- 上传校验权限、大小、扩展名、MIME 和文件头。
- 多微信号无法完全由公众号静默识别；建议结合关注门槛、设备/IP 风控、低价值每日限额和异常人工审计，不采用无法核真的学号。

## 9. 交付前检查

- 运行全部 Maven 测试和 Vue 生产构建。
- 检查仓库不存在 `.env`、AppSecret、数据库真实密码、日志、上传文件和业务数据。
- 使用手机微信验证 OAuth、关注、分享卡片、助力续办、转盘和券包。
- 使用实体手机测试商户全屏扫码、返回填码、确认核销和重复核销。
- 使用两个并发请求验证同一 `requestId` 不重复扣库存。
- 生产数据库和上传目录设置定时备份；上线前更换若依默认管理员密码。
